# Pylentra 0.6.0 — Esportare e importare la libreria

- **Data:** 2026-10-30
- **Stato:** in revisione
- **Base:** 0.5.0 (`main` a a932255)
- **Issue:** [#15](https://github.com/LuuckA21/pylentra/issues/15)

## 1. Obiettivo

Portare la libreria su un altro PC, o farne un backup, con un file solo.

**Criteri di successo**

- "Esporta…" scrive un file TOML con gruppi, connessioni (forward, note,
  colori, icone compresi) e snippet, dove sceglie l'utente.
- Nel file non c'è mai un segreto: password e passphrase restano nel
  portachiavi, delle chiavi c'è solo il percorso.
- "Importa…" su un altro PC mostra un'anteprima; confermando, le connessioni
  scelte arrivano con gruppi, jump host e snippet collegati.
- Importare due volte lo stesso file non duplica nulla di default: le
  connessioni con lo stesso nome sono deselezionate, i gruppi con lo stesso
  nome sono riusati.
- Un file di una versione futura viene rifiutato con un messaggio chiaro.

**Fuori ambito:** impostazioni dell'app; esportare una parte sola della
libreria; cifrare il file; importare segreti; SFTP, tag, broadcast (#11, #17,
#22).

## 2. Decisioni

| Area | Scelta |
|---|---|
| Scelta del file | dialoghi di sistema "Salva con nome" / "Apri" con `tauri-plugin-dialog` |
| Formato | TOML, `format = "pylentra-export"`, `version = 1` |
| Contenuto | tutta la libreria e tutti gli snippet; niente impostazioni |
| Id | sempre nuovi all'import; i riferimenti seguono |
| Gruppi | uniti per nome (riusa l'esistente), gli altri creati |
| Duplicati | connessione con lo stesso nome: segnalata e non selezionata di default |
| Jump host non importato | riusa una connessione esistente con lo stesso nome, altrimenti nessun jump host (con nota) |
| Scritture | una per `connections.toml`, una per `snippets.toml`; un errore prima di scrivere annulla tutto |

Dipendenza nuova: `tauri-plugin-dialog` (crate in `src-tauri`, pacchetto npm
`@tauri-apps/plugin-dialog`), con i soli permessi `dialog:allow-save` e
`dialog:allow-open`.

## 3. Formato del file

```toml
format = "pylentra-export"
version = 1
exported_at = "2026-10-30T09:12:00Z"

[[groups]]
id = "…"
name = "Produzione"
color = "Red"

[[connections]]
id = "…"
name = "web-1"
group_id = "…"            # un id di [[groups]] di questo file
host = "10.0.0.5"
username = "deploy"
jump_via = "…"            # un id di [[connections]] di questo file
auth = { type = "Key", path = "~/.ssh/id_ed25519", save_passphrase = false }
# forwards, notes, color, icon come in connections.toml

[[snippets]]
id = "…"
name = "Log"
text = "tail -f /var/log/{{servizio}}.log"
connection_id = "…"       # facoltativo: un id di [[connections]] di questo file
```

- I tipi sono quelli di `connections.toml` e `snippets.toml`
  (`Group`, `Connection`, `Snippet`); i campi `extra` non vengono scritti.
- `version` è propria del file di export e indipendente da
  `CONNECTIONS_VERSION` e `SNIPPETS_VERSION`.
- Lettura: `format` diverso → errore "non è un export di Pylentra";
  `version` maggiore di `EXPORT_VERSION` → errore "creato da una versione più
  recente"; TOML non valido → errore col motivo. Il file è letto solo se è un
  file normale e al massimo 5 MB.

## 4. Core (`crates/pylentra-core/src/export.rs`, nuovo)

```rust
pub const EXPORT_FORMAT: &str = "pylentra-export";
pub const EXPORT_VERSION: u32 = 1;

pub struct ExportFile { format, version, exported_at, groups, connections, snippets }

pub fn export(library: &Library, snippets: &[Snippet], now: &str) -> Result<String, CoreError>;
pub fn parse(text: &str) -> Result<ExportFile, CoreError>;
pub fn preview(file: &ExportFile, library: &Library, key_exists: impl Fn(&Path) -> bool) -> ImportPreview;
pub fn plan(file: &ExportFile, selected: &[Uuid], library: &Library) -> Result<ImportPlan, CoreError>;
```

- `ImportPreview` (esportato in TS): una riga per connessione del file
  `{ id, name, target: "user@host:port", group: Option<String>, duplicate,
  missing_key: Option<String>, jump: Option<JumpNote> }`, dove `JumpNote` è
  `InFile(name)` (il jump host è nel file), `Existing(name)` (riusa una
  connessione presente con quel nome) o `Dropped(name)` (resterà senza);
  più `groups_new`, `groups_reused`, `snippets_global`,
  `snippets_per_connection`.
- `duplicate`: esiste già una connessione con lo stesso nome (confronto
  esatto, maiuscole comprese).
- `missing_key`: per `Key { path }` con `key_exists(path)` falso; `~` è
  espanso come fa la connessione.
- `plan`: per le connessioni selezionate crea id nuovi e una mappa
  vecchio → nuovo; `group_id` va al gruppo esistente con lo stesso nome o a
  uno nuovo (creato solo se usato da una connessione selezionata); `jump_via`
  va al nuovo id se il jump host è selezionato, altrimenti all'esistente con
  lo stesso nome, altrimenti `None`; gli snippet globali arrivano tutti con id
  nuovi, quelli di una connessione solo se la connessione è selezionata. Un
  id selezionato che non è nel file è un errore.
- `export` toglie `extra` da gruppi, connessioni e snippet.

## 5. Store

- `ConnectionStore::import_bundle(groups: Vec<Group>, conns: Vec<Connection>) -> Result<usize, CoreError>`:
  stessa validazione di `import` (connessioni valide, id unici, jump host
  esistenti, catene senza cicli), più i gruppi nuovi; una sola scrittura;
  rifiutata se la libreria è in sola lettura. `import` (da `~/.ssh/config`)
  resta com'è.
- `SnippetStore::import(snippets: Vec<Snippet>) -> Result<usize, CoreError>`:
  una sola scrittura; rifiutata se `snippets.toml` è in sola lettura o non
  disponibile.
- Ordine in `library_import`: prima la libreria, poi gli snippet; se gli
  snippet falliscono le connessioni restano importate e l'errore è mostrato
  ("connessioni importate, snippet no: <motivo>"), come oggi per la
  cancellazione di una connessione.

## 6. Comandi (`src-tauri/src/commands.rs`)

- `library_export(path: String) -> Result<(), ApiError>`: `export` + scrittura
  atomica.
- `library_import_preview(path: String) -> Result<ImportPreview, ApiError>`.
- `library_import(path: String, selected: Vec<Uuid>) -> Result<ImportCounts, ApiError>`
  con `ImportCounts { connections, groups, snippets }`: rilegge e rianalizza il
  file (la selezione usa gli id del file, stabili tra anteprima e conferma).
- Tutti `async`/fuori dal thread principale come `ssh_config_scan`; lettura
  con lo stesso controllo (file normale, 5 MB).

## 7. Interfaccia

- **Impostazioni → Libreria** (nuova sezione): "Esporta…" e "Importa…" con una
  riga di spiegazione ("Nessuna password viene esportata").
- **Barra laterale, menu "⋯":** "Esporta libreria…" e "Importa libreria…"
  accanto a "Importa da ~/.ssh/config".
- **Esporta:** dialogo "Salva con nome" con nome proposto
  `pylentra-export-AAAA-MM-GG.toml` e filtro `.toml`; poi un avviso "Libreria
  esportata in <percorso>". Annullare il dialogo non fa nulla.
- **Importa:** dialogo "Apri" con filtro `.toml`; poi `LibraryImportDialog`:
  - una riga per connessione con casella, nome, `user@host`, gruppo;
  - le duplicate deselezionate con la pillola "già presente";
  - avviso "chiave non trovata: <percorso>" e nota del jump host
    (`Dropped`: "resterà senza jump host");
  - in fondo: gruppi nuovi/riusati e snippet che arriveranno;
  - "Importa (N)" disattivato con N = 0; a fine import un avviso
    "Importate N connessioni, G gruppi, S snippet".
- Libreria in sola lettura: "Importa…" disattivato con il motivo, come gli
  altri comandi di modifica; "Esporta…" resta.
- Errori di lettura (versione futura, formato, TOML) nel dialogo, prima
  dell'anteprima.
- Stile e accessibilità di `ImportDialog` (righe, caselle, `role="dialog"`).

## 8. Test

- **Core (`export.rs`):** andata e ritorno (export → parse → plan di tutto in
  una libreria vuota dà gli stessi gruppi, connessioni e snippet con id nuovi
  e riferimenti coerenti); nessuna password nel testo (solo `save`); `format`
  sbagliato, `version` 2 e TOML rotto rifiutati; `extra` non esportati;
  `preview`: duplicato per nome, chiave mancante (con `key_exists` finto), le
  tre note del jump host, conteggi; `plan`: gruppo riusato per nome, jump host
  selezionato / esistente / perso, snippet della connessione non selezionata
  scartato, id sconosciuto → errore.
- **Store:** `import_bundle` scrive una volta sola; un errore non scrive
  niente; sola lettura rifiutata. `SnippetStore::import` idem.
- **Comandi:** file oltre 5 MB e cartella rifiutati; andata e ritorno su file
  temporaneo.
- **UI:** dialoghi del plugin finti; annullare non chiama i comandi;
  anteprima con duplicati deselezionati; "Importa (N)"; riepilogo; errore di
  versione mostrato.

## 9. Compatibilità

Nessun file esistente cambia formato: tornare alla 0.5.x non perde nulla. Un
file di export della 0.6 non è leggibile dalle versioni precedenti (non hanno
l'import), e le versioni successive leggono `version = 1`.
