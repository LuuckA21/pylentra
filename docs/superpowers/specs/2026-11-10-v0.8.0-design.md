# Pylentra 0.8.0 — SFTP: pannello file accanto al terminale

- **Data:** 2026-11-10
- **Stato:** in revisione
- **Base:** 0.7.2 (`main` a 32ec822)
- **Issue:** [#11](https://github.com/LuuckA21/pylentra/issues/11)

## 1. Obiettivo

Sfogliare i file del server e trasferirli dalla stessa sessione SSH, senza
aprire un altro programma.

**Criteri di successo**

- Il pulsante "File" nella barra di stato di un pannello terminale apre, a
  destra del terminale, la home dell'utente sul server di quella sessione.
- Si scaricano e caricano file e cartelle intere, con avanzamento, coda e
  Annulla.
- Un trasferimento interrotto non lascia mai un file troncato, e un file
  esistente non viene toccato finché il nuovo non è completo.
- Nessun file viene mai letto o scritto fuori dalla cartella scelta, qualunque
  cosa mandi il server.
- L'interfaccia web non può mai indicare a Rust un percorso locale.

**Fuori ambito (prima versione):** nuova cartella, rinomina, elimina; modifica
dei permessi; editor integrato; trascinare dal pannello verso il file manager;
riprendere un trasferimento interrotto; tag e broadcast (#17, #22).

## 2. Decisioni

| Area                          | Scelta                                                                                                            |

## 3. Core: `crates/pylentra-core/src/ssh/sftp.rs` (nuovo)

### Avvio

- `Command::SftpOpen(reply)` nuovo nel task della sessione. Viene accettato
  solo dopo `Ready` (prima risponde "la sessione non è pronta", come
  `ForwardStart`).
- Il task apre `channel_open_session` + `request_subsystem("sftp")` sulla
  `chain.target`, crea `RawSftpSession` sul canale (`into_stream`), fa `init`
  e legge le estensioni che servono: `posix-rename@openssh.com` e
  `limits@openssh.com`.
- Da lì in poi l'SFTP vive in un compito proprio (`Sftp`), con la sua coda,
  così un trasferimento lungo non rallenta mai il terminale. Il task della
  sessione tiene solo il suo `JoinHandle` e il mittente della coda.
- Chiudere la sessione (o la sua fine) chiude il canale SFTP, svuota la coda,
  annulla il trasferimento in corso e cancella i temporanei.
- Una seconda apertura riusa l'SFTP già aperto.

### API del `SessionManager`

Stesso schema dei forward (`send` + `oneshot`):

```rust
pub async fn sftp_list(&self, id: SessionId, dir: String) -> Result<Listing, CoreError>;
pub async fn sftp_download(&self, id: SessionId, items: Vec<String>, local_dir: PathBuf) -> Result<u32, CoreError>;
pub async fn sftp_upload(&self, id: SessionId, items: Vec<PathBuf>, remote_dir: String) -> Result<u32, CoreError>;
pub async fn sftp_cancel(&self, id: SessionId, transfer_id: u32) -> Result<(), CoreError>;
```

- `Listing { dir: String /* canonico */, entries: Vec<Entry>, truncated: bool }`;
  `Entry { name, kind: File | Dir | Link | Other, size: Option<u64>, modified: Option<u64> }`.
  Le voci con un nome non valido (§4) non vengono restituite.
- `sftp_download` e `sftp_upload` mettono in coda e restituiscono subito il
  `transfer_id`. Tutto il resto arriva come eventi.

### Eventi

```rust
SessionEvent::Transfer { transfer_id: u32, state: TransferState }

enum TransferState {
    Queued { direction: Up | Down, name: String },
    Running { done_bytes: u64, total_bytes: Option<u64>, files_done: u32, current: String },
    Conflict { name: String },           // in attesa di PromptAnswer::Conflict
    Finished { files: u32, skipped: Vec<Skipped> },
    Failed { error: ApiError, files: u32, skipped: Vec<Skipped> },
    Cancelled { files: u32 },
}
struct Skipped { path: String, reason: SkipReason }   // relativo alla cartella trasferita
enum SkipReason { Symlink, Special, InvalidName, Exists, Error { error: ApiError } }
```

- `Running` si invia al massimo ogni 200 ms e alla fine di ogni file.
- `total_bytes` è noto dopo la scansione (vedi sotto). La scansione conta file
  e byte senza trasferire nulla e si ferma ai limiti (§4).

### Domanda dei conflitti

- `PromptAnswer::Conflict { choice: Overwrite | Skip | Cancel, all: bool }`
  nuovo. Si chiede con `PromptBroker::ask`, che oggi chiede password e chiave
  del server.
- Dopo `Ready` non c'è altra domanda in corso nella sessione, quindi le due
  cose non si sovrappongono.
- Una domanda lasciata senza risposta (sessione chiusa) vale `Cancel`, come
  oggi.
- Con `all: true` la scelta vale per il resto di quel trasferimento.

### Trasferimento

1. **Scansione:** elenco piatto dei file da trasferire (percorso relativo,
   dimensione, data), cartelle comprese, applicando le regole del §4. Non
   segue mai link.
2. **Per ogni cartella:** la crea se manca. Se esiste ed è una cartella vera,
   la usa. Altrimenti (link, file) la salta con tutto il suo contenuto.
3. **Per ogni file:**
   - Se la destinazione esiste: link simbolico → `Skipped(Symlink)`; altrimenti
     si fa la domanda dei conflitti.
   - Si scrive un temporaneo esclusivo accanto alla destinazione: in locale
     con `create_new`, sul server con `CREATE | EXCL`. Nome:
     `<nome>.<n>.pylentra-tmp`, con `n` crescente se il nome è già preso.
   - A scrittura completa, si imposta la data di modifica e si rinomina sopra
     la destinazione:
     - in locale con `fs::rename`, che sostituisce sia su Unix sia su Windows;
     - sul server con `posix-rename@openssh.com`;
     - se il server non lo supporta: `remove` della destinazione e poi
       `rename`. Il vecchio file sparisce solo quando il nuovo è completo.
   - Su errore o Annulla si cancella il temporaneo.
4. **Lettura e scrittura a blocchi**, mai il file intero in memoria:
   - blocchi di 32 KiB, o meno se `limits@openssh.com` lo chiede;
   - fino a 8 richieste in volo per file, così la latenza del server non
     limita la velocità;
   - le scritture si applicano in ordine di offset, quindi il temporaneo non
     ha mai buchi;
   - memoria massima per trasferimento: 8 × 32 KiB.
5. **Errori:**
   - un errore su un singolo file (permesso negato, file sparito) lo mette in
     `Skipped(Error)` e la coda prosegue;
   - un errore della connessione o del canale porta a `Failed` e alla fine
     della coda.

### Temporanei in locale: riuso di `atomic_write`

`store::atomic_write` oggi crea `<path>.<n>.tmp` con `create_new`, scrive e
rinomina. La parte "crea il temporaneo esclusivo" diventa
`store::create_temp(path) -> (PathBuf, File)`, usata sia da `atomic_write` sia
dal download. Nessuna seconda implementazione.

## 4. Regole di sicurezza

1. **Percorsi locali solo da Rust.**
   - I file da caricare arrivano solo dal dialog aperto da Rust o dal
     trascinamento ricevuto da Rust (§5).
   - La cartella di download arriva solo dal dialog.
   - Nessun comando accetta un percorso locale dall'interfaccia.
2. **Nomi dal server controllati a ogni livello.** Ogni nome ricevuto (elenco
   e scansione, anche nelle sottocartelle) deve essere un solo componente
   valido. Altrimenti `InvalidName`: in un elenco la voce non compare, in un
   trasferimento è saltata ed elencata. Non valido significa:
   - vuoto, `.`, `..`, con `/`, `\`, NUL o caratteri di controllo (U+0000–U+001F,
     U+007F);
   - su Windows anche: `<>:"|?*`, che finisce con punto o spazio, nomi
     riservati (`CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`, anche
     con estensione).
3. **Mai seguire link né file speciali.** Si legge il tipo senza seguire i link:
   `lstat` / `readdir` sul server, `symlink_metadata` in locale. Link simbolici
   → `Symlink`; pipe, dispositivi, socket → `Special`.
4. **Nessuna uscita dalla destinazione.** I percorsi di destinazione si
   costruiscono solo come cartella scelta + nomi validati. Un elemento già
   presente nel percorso che è un link si salta (§3, passi 2 e 3).
5. **Temporanei esclusivi** su entrambi i lati: non si sovrascrive mai un file
   che ha per caso lo stesso nome.
6. **Limiti contro un server malevolo.** Superato un limite il trasferimento va
   in `Failed` con `sftp.limit`; quanto già completato resta. Un elenco di
   cartella si tronca con `truncated: true`.
   - profondità massima 32 livelli;
   - al massimo 100.000 elementi per trasferimento;
   - al massimo 100.000 voci per elenco di cartella.
7. **Log:** solo codici di errore e id; mai percorsi, nomi o contenuti.

## 5. Comandi Tauri e trascinamento (`src-tauri/src`)

- `sftp_list(session_id, dir)` → `Listing`.
- `sftp_download(window, session_id, items)`: apre il dialog "scegli cartella"
  (da Rust, come l'export), poi `SessionManager::sftp_download`. Annullare il
  dialog restituisce `None`.
- `sftp_upload_pick(window, session_id, remote_dir, folder: bool)`: apre il
  dialog file (multiplo) o cartella, poi `sftp_upload`.
- `sftp_upload_drop(session_id, drop_id, remote_dir)`: prende i percorsi del
  rilascio `drop_id` e chiama `sftp_upload`.
- `sftp_cancel(session_id, transfer_id)`.
- Le risposte ai conflitti passano dal comando `session_answer`, che esiste già.
- **Trascinamento:**
  - `main.rs` ascolta `WindowEvent::DragDrop(Drop { paths, position })` e tiene
    i percorsi in `AppState.pending_drop: Mutex<Option<(u64, Vec<PathBuf>)>>`;
    ogni rilascio sostituisce il precedente.
  - Emette all'interfaccia `files-dropped { drop_id, names, x, y }`, dove
    `names` sono solo i nomi finali. L'interfaccia trova il pannello file sotto
    `(x, y)` e chiama `sftp_upload_drop`; se non ce n'è nessuno, il rilascio
    scade al successivo.
  - `drop_id` vale una volta sola.
- **Impostazioni:** `sftp_show_hidden: bool` (default `false`) e
  `sftp_panel_width: f32` (frazione, default `0.3`, valida 0,15–0,6, limitata al
  caricamento come i timeout).

## 6. Interfaccia (`ui/`)

- **`StatusBar`:** pulsante "File" accanto a "Forward", attivo con la sessione
  pronta.
- **`FilePanel.svelte` (nuovo)**, a destra del terminale dentro `TerminalPane`.
  Il bordo è trascinabile e da tastiera, con la stessa logica dei divisori
  dello split. Contiene:
  - riga del percorso: cartella, "Su", "Aggiorna", "Mostra nascosti";
  - elenco: cartelle prima, poi file, ordinati con `byName`; nome, dimensione,
    data;
  - selezione multipla (clic, Ctrl+clic, Shift+clic; Spazio, Shift+frecce);
    Invio o doppio clic apre una cartella, Backspace sale;
  - pulsanti "Carica file", "Carica cartella", "Scarica";
  - coda dei trasferimenti: nome, barra, Annulla. A fine trasferimento un
    riepilogo ("12 file, 3 saltati") che si espande nei saltati con il motivo;
  - zona di rilascio evidenziata durante il trascinamento: si usano gli eventi
    drag-over/leave della webview, solo per la grafica.
- **Domanda dei conflitti:** riquadro nel pannello terminale, come
  `SecretPrompt`: nome del file, Sovrascrivi / Salta / Annulla, "applica a
  tutti".
- **Store:** lo stato SFTP del pannello (cartella, elenco, coda) sta nel
  `PaneState` del `sessionReducer`, aggiornato dagli eventi `Transfer` come
  oggi i `Forward`.
- **Testi:** chiavi `sftp.*` ed `error.sftp.*` in italiano e inglese.

## 7. Errori

Nuovi codici di `CoreError`, con voce in `CORE_CODES` e nelle traduzioni:

| Codice                   | Quando                                   |
| ------------------------ | ---------------------------------------- |
| `sftp.unavailable`       | il server rifiuta il sottosistema `sftp` |
| `sftp.permission_denied` | permesso negato                          |
| `sftp.limit`             | superata profondità o numero di elementi |

Si riusano i codici esistenti: `not_found` (file o cartella spariti),
`cancelled` (Annulla), `io` (errori locali). Gli altri errori del server SFTP
diventano `ssh.protocol` con il messaggio.

## 9. Compatibilità

- Nessun file cambia formato. `settings.toml` ha due campi in più, che la
  0.7.x conserva (campi sconosciuti mantenuti dalla 0.4.0): tornare indietro
  non perde nulla.
- Dipendenze nuove: `russh-sftp`, più `dashmap` e `serde_bytes`. Da
  verificare con `cargo deny`.
