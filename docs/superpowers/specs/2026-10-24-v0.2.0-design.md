# Pylentra 0.2.0 — Aspetto e qualità della vita

- **Data:** 2026-10-24
- **Stato:** in revisione
- **Base:** 0.1.1 (`main` a 273a406)
- **Mockup:** tela "Pylentra 0.2.0 — direzione visiva" (artifact privato), schede
  "C · Morbido" e "C · Impostazioni (Terminale)"

## 1. Obiettivo

La 0.1 funziona ma "sembra spoglia, poco curata". La 0.2.0 rifà l'aspetto
nello stile C (morbido, alla Warp) e aggiunge quattro migliorie richieste:

1. impostazioni più definite, divise per categoria;
2. connessione rapida `utente@host:porta`;
3. import da `~/.ssh/config`;
4. colori e icone per connessione.

**Criteri di successo**

- Tutte le schermate (finestra principale, modulo connessione, dialoghi,
  impostazioni, overlay del terminale) usano il nuovo sistema visivo, in tema
  chiaro e scuro, con contrasto AA (4,5:1) sui testi.
- Ci si connette a un host non salvato scrivendo `utente@host` e premendo Invio,
  e la sessione si può poi salvare senza riconnettersi.
- Un `~/.ssh/config` tipico (blocchi `Host`, `Host *` con valori predefiniti,
  `IdentityFile`, `ProxyJump` a un alias, forward locali) si importa in un passo
  con anteprima, senza duplicati.
- Una libreria e delle impostazioni della 0.1 si aprono senza perdita di dati;
  la 0.1 apre una libreria della 0.2 in sola lettura, senza poterla corrompere.

**Fuori ambito:** cronologia degli indirizzi scritti a mano, sincronizzazione
continua con `~/.ssh/config`, `Include`/`Match`/`ProxyCommand`/`DynamicForward`,
jump host a più salti nell'import, tipo di chiave host nella barra di stato,
gestione delle voci di `~/.ssh/known_hosts`.

## 2. Decisioni

| Area | Scelta |
|---|---|
| Stile | C · Morbido: pannelli arrotondati, superfici a livelli, molta aria, accento viola |
| Implementazione | token CSS in `ui/src/app.css` + pochi componenti propri; nessuna libreria di componenti, niente Tailwind |
| Font UI | Manrope variabile, incluso nell'app (`@fontsource-variable/manrope`, OFL) |
| Colori connessione | nome di colore (8) salvato nel file, risolto dai token del tema |
| Preferenze locali | `localStorage` della webview (recenti, larghezza e stato della barra laterale, categoria aperta) |
| Formato libreria | `connections.toml` passa alla versione 2 |
| Parser ssh_config | scritto nel core, senza nuove dipendenze |

## 5. Colori e icone

### 5.1 Modello (`crates/pylentra-core/src/model.rs`)

```rust
#[serde(rename_all = "snake_case")]
pub enum TagColor { Red, Orange, Amber, Green, Teal, Blue, Violet, Gray }

#[serde(rename_all = "snake_case")]
pub enum ConnIcon { Server, Database, Web, Nas, Raspberry, Cloud, Container, Terminal }

// Group
#[serde(default, skip_serializing_if = "Option::is_none", deserialize_with = "lenient")]
pub color: Option<TagColor>,

// Connection
pub color: Option<TagColor>,   // None = eredita dal gruppo (stessi attributi)
pub icon: Option<ConnIcon>,    // None = iniziali (stessi attributi)
```

`lenient` deserializza un valore sconosciuto come `None` invece di fallire, così
una versione futura con colori o icone nuove non rende illeggibile il file.

### 5.2 Regole di visualizzazione (`ui/src/lib/appearance.ts`)

- `colorOf(conn, groups)`: `conn.color ?? group?.color ?? null` (`null` = neutro).
- `initialsOf(name)`: prime lettere dei segmenti separati da `-`, `_`, `.` o
  spazio, massimo due, maiuscole; con un solo segmento le prime due lettere
  ("nas" → "NA"); senza lettere né cifre → "?".
- Avatar, pallino della scheda e pillola della barra di stato usano solo queste
  due funzioni.

### 5.3 Dove si sceglie

- **Modulo connessione:** anteprima dell'`Avatar` accanto al nome; sezione
  "Aspetto" con un gruppo di radio per l'icona ("Iniziali" + 8) e uno per il
  colore ("Dal gruppo" + 8 campioni).
- **Dialogo gruppo:** nome + gruppo di radio per il colore ("Nessuno" + 8).
- Connessioni importate o salvate dalla connessione rapida: senza colore né icona.

### 5.4 Test

Core: i nuovi campi si salvano e si rileggono uguali; un file senza i campi si
carica; `color = "pink"` e `icon = "rocket"` danno `None`; i campi `None` non
compaiono nel TOML. UI: `colorOf`, `initialsOf` (un carattere, solo simboli,
lettere accentate, più di due segmenti), i selettori del modulo e del gruppo
salvano il valore scelto.

## 6. Connessione rapida

### 6.1 Campo e suggerimenti

Nella barra delle sessioni e nella schermata di benvenuto. Mentre si scrive, un
menu (`role="listbox"`, navigazione con ↑/↓, Invio, Esc) elenca le connessioni
salvate che corrispondono (via `search.ts`, massimo 6) e come ultima voce
"Connetti a `<testo>`", che è anche l'azione di Invio senza selezione.

### 6.2 Interpretazione (`ui/src/lib/quickTarget.ts`)

Funzione pura `parseTarget(text, defaults) → { user, host, port } | { error }`:

- forma `[utente@]host[:porta]`; IPv6 tra parentesi quadre (`[::1]:2222`);
- spazi iniziali e finali ignorati; spazi interni, più di una `@`, utente o host
  vuoti → errore;
- utente mancante → `defaults.user` (impostazione `default_user`); se manca
  anche quello → errore "Aggiungi utente@";
- porta mancante → `defaults.port`; porta non numerica o fuori da 1–65535 →
  errore.

L'errore compare sotto il campo; non si tenta la connessione.

### 6.3 Autenticazione `Auto`

Nuova variante `AuthMethod::Auto` (TOML: `auth = { type = "Auto" }`). Prova in
ordine, fermandosi al primo successo:

1. agent SSH, se raggiungibile (agent assente = salta, non errore);
2. `~/.ssh/id_ed25519`, `~/.ssh/id_ecdsa`, `~/.ssh/id_rsa` che esistono, con la
   richiesta di passphrase di oggi (senza opzione di salvarla);
3. password o keyboard-interactive con la richiesta di oggi (senza salvataggio).

Se tutto fallisce: `auth.all_failed` come oggi. È anche il metodo predefinito per
gli host importati senza `IdentityFile`. Il modulo connessione lo offre come
"Automatico".

### 6.4 Backend

Comando `session_open_quick(connection, cols, rows, data, events)`: riceve una
`Connection` costruita dall'interfaccia (id nuovo, `jump_via = None`,
`forwards` vuoti, `auth = Auto`), la valida con `Connection::validate`, rifiuta
`jump_via` o forward non vuoti con `config.invalid`, e apre la sessione con la
catena `[connection]` senza scriverla nella libreria. Verifica della chiave host
identica alle sessioni salvate.

### 6.5 Scheda e salvataggio

La scheda si chiama `utente@host` e tiene la `Connection` effimera nel suo
stato (`TabState.quick?: Connection`). Ha il pulsante "Salva connessione": apre
il modulo nuova connessione precompilato (nome = host, `Auto`); al salvataggio
la scheda prende `connectionId` della connessione salvata e perde `quick`: nome,
colore e "Riconnetti" seguono la connessione salvata. La sessione aperta non si
interrompe.

### 6.6 Test

`quickTarget.ts`: con e senza utente e porta, IPv6 con e senza porta, porta 0 e
65536, testo vuoto, spazi interni, doppia `@`, utente predefinito presente e
assente. `Auto` contro il server di test esistente: agent presente, agent assente
con una sola chiave predefinita in una HOME di prova, nessuna chiave → password.
`session_open_quick`: rifiuta jump e forward. UI: suggerimenti e Invio, "Salva
connessione" collega la scheda.

## 7. Import da `~/.ssh/config`

### 7.1 Lettura (`crates/pylentra-core/src/ssh_config.rs`)

`parse(text: &str) -> ScanResult { candidates, skipped: Vec<FileNote> }`,
funzione pura.

- Righe `parola chiave valore` o `parola chiave=valore`; parole chiave senza
  distinzione di maiuscole; valori tra virgolette; commenti `#`; righe vuote.
- Ogni alias senza `*` o `?` di ogni riga `Host` è un candidato; `Host a b` dà
  due candidati.
- Per ogni candidato si scorrono **tutti** i blocchi `Host` nell'ordine del file
  e, per ogni parola chiave, vale il **primo** valore trovato nei blocchi che
  corrispondono all'alias (pattern con `*`, `?`, negazione `!`: un pattern
  negato che corrisponde esclude il blocco). Così `Host *` in fondo fornisce i
  valori predefiniti, come in OpenSSH.
- `Include` e blocchi `Match` vengono saltati e riportati in `skipped` con il
  numero di riga.

| ssh_config | Pylentra | Nota se non convertibile |
|---|---|---|
| alias | `name` | |
| `HostName` | `host` (se manca: l'alias) | |
| `Port` | `port` (se manca: 22) | porta non valida → candidato con errore, non selezionabile |
| `User` | `username` | se manca: vedi §7.3 |
| primo `IdentityFile` | `Key { path, save_passphrase: false }` | percorso con `%` → `Auto` + nota |
| nessun `IdentityFile` | `Auto` | |
| `ProxyJump <alias>` | `jump_via` = id del candidato o della connessione salvata con quel nome | più salti, `utente@host`, alias sconosciuto → nessun jump + nota; `none` → nessun jump |
| `LocalForward [ind:]porta host:porta` | `ForwardRule::Local` (`auto_start: false`) | |
| `RemoteForward porta host:porta` | `ForwardRule::Remote` (`auto_start: false`) | indirizzo remoto di ascolto ignorato + nota |
| `DynamicForward`, `ProxyCommand` | — | nota |

Ogni candidato: `Connection` proposta (con un `Uuid` nuovo), note, `exists`
(nome uguale a una connessione salvata, senza distinzione di maiuscole),
`needs_user`.

### 7.2 Comandi (`src-tauri`)

- `ssh_config_scan() -> ScanResult`: legge `~/.ssh/config`
  (`%USERPROFILE%\.ssh\config` su Windows). File assente → risultato vuoto con
  `missing: true`; oltre 1 MB → `config.invalid`; byte non UTF-8 convertiti con
  `from_utf8_lossy`. Calcola `exists` sulla libreria attuale.
- `connections_import(connections: Vec<Connection>, group_id: Option<Uuid>)`:
  aggiunge tutte le connessioni con **una sola** scrittura atomica, applicando la
  stessa validazione di `upsert_connection` all'insieme (catene di jump, nomi,
  porte). Un errore annulla tutto. Libreria in sola lettura → `config.read_only`.
  Restituisce il numero importato.

`~/.ssh/config` non viene mai scritto. Le chiavi non vengono lette, solo il
percorso viene salvato.

### 7.3 Anteprima (`ImportDialog.svelte`)

- Riga per candidato: casella, `Avatar` neutro, nome, `utente@host:porta`,
  metodo di autenticazione, note sotto in piccolo.
- `exists` → casella disattivata e "già presente"; candidati con errore →
  disattivati con il motivo; gli altri spuntati.
- Spuntare un candidato che ha `jump_via` verso un altro candidato spunta anche
  quello ("necessario per …"); togliere la spunta al jump host toglie `jump_via`
  dalle connessioni che lo usano e aggiunge una nota.
- Se almeno un candidato spuntato ha `needs_user`: campo "Utente per gli host
  senza User", precompilato con `default_user`, obbligatorio.
- "Gruppo di destinazione": "Nessun gruppo" (predefinito), gruppi esistenti,
  "Nuovo gruppo 'ssh config'" (creato con `group_save` prima dell'import).
- In cima: avvisi da `skipped`; file assente → messaggio con il percorso cercato.
- "Importa N connessioni", disattivato con N = 0 o libreria in sola lettura;
  al termine toast "Importate N connessioni" e chiusura.

### 7.4 Test

Parser (fixture in `crates/pylentra-core/tests/fixtures/ssh_config/`): `Host *`
in fondo e regola del primo valore; più alias per riga; negazione; `=` e
virgolette; commenti e righe vuote; `Include` e `Match` saltati con riga;
`ProxyJump` ad alias, multiplo, `utente@host`, `none`; forward locali e remoti;
`IdentityFile` con `%d`; file vuoto. Comandi: file assente, file > 1 MB, byte
non UTF-8, `exists`. Import: jump tra connessioni nuove in una scrittura; una
connessione non valida → file invariato; libreria in sola lettura rifiutata.
UI: spunta automatica del jump host e rimozione, `exists` disattivato, campo
utente obbligatorio.

## 8. Impostazioni

### 8.1 Finestra

Dialogo modale ~920×640, `--radius-xl`. A sinistra le categorie (Aspetto,
Terminale, Connessioni, Sicurezza, Aggiornamenti), in fondo versione installata
e "Apri cartella log". Sotto 760px di larghezza le categorie diventano pillole in
alto. Ogni controllo salva al cambio, come oggi. Ultima categoria aperta in
`localStorage` (`pylentra.settings.section`).

### 8.2 Modello (`Settings` in `model.rs`, `#[serde(default)]` già presente)

| Categoria | Campo | Tipo e intervallo | Predefinito |
|---|---|---|---|
| Aspetto | `theme`, `language` | invariati | invariati |
| Terminale | `font_family`, `font_size` | invariati (spostati da Aspetto) | invariati |
| | `terminal_theme` | `app` \| `dracula` \| `nord` \| `solarized_dark` \| `solarized_light` | `app` |
| | `cursor_style` | `block` \| `bar` \| `underline` | `block` |
| | `cursor_blink` | bool | `true` |
| | `scrollback` | 1 000–100 000 | 10 000 |
| | `copy_on_select` | bool | `false` |
| Connessioni | `default_user` | `Option<String>` | `None` |
| | `default_port` | 1–65535 | 22 |
| | `connect_timeout_secs` | 5–120 | 15 |
| | `keepalive_secs` | 0 (spento) o 5–300 | 30 |
| | `auto_reconnect` | bool | `false` |
| Sicurezza | `confirm_close_active` | bool | `true` |
| Aggiornamenti | `check_updates` | bool | `true` |

`terminal_theme` e `cursor_style` si leggono con `lenient` (valore sconosciuto →
predefinito). `Settings::validate()` controlla gli intervalli; `settings_save`
rifiuta valori fuori intervallo con `config.invalid`. Un `settings.toml` della
0.1 si carica con i nuovi campi ai predefiniti.

### 8.3 Comportamento

- **Terminale.** Le palette sono costanti in `ui/src/lib/terminalThemes.ts`
  (valori dai progetti originali: Dracula MIT, Nord MIT, Solarized MIT; licenze
  citate nel file). `app` usa il codice attuale che legge i token CSS. Tutte le
  opzioni si applicano subito alle schede aperte (`term.options`). Anteprima
  statica sotto i controlli.
- **Connessioni.** `do_session_open` e `session_open_quick` costruiscono
  `SessionOptions` dalle impostazioni correnti (`connect_timeout`,
  `keepalive_interval`; `keepalive_secs = 0` disattiva il keepalive). Le sessioni
  aperte non cambiano.
- **Riconnessione automatica.** Con `auto_reconnect` attivo, una scheda che era
  arrivata a `ready` e riceve `Closed { Error }` con codice `network.*`,
  `ssh.protocol` o `io` riprova dopo 1, 2, 5, 10, 30 secondi (5 tentativi) nella
  stessa scheda. Overlay "Riconnessione… tentativo n di 5" con "Annulla". Non
  riprova per `auth.*`, `hostkey.*`, `Exited`, `UserClosed`, né se la scheda non
  era mai arrivata a `ready`. Le richieste di segreti compaiono come oggi.
- **Sicurezza.** Con `confirm_close_active`, chiudere una scheda in `ready` (×,
  Ctrl+Shift+W) o la finestra con sessioni `ready` chiede conferma (la finestra
  tramite l'evento di chiusura di Tauri). Elenco delle chiavi host: nuovo
  `KnownHosts::list() -> Vec<KnownHostEntry { host, port, algo, fingerprint }>`
  sul solo file di Pylentra (righe con host hashato mostrate come "voce
  cifrata"), comando `known_hosts_list`, "Elimina" usa `known_host_forget`. Nota
  in fondo: le voci di `~/.ssh/known_hosts` sono usate in lettura e non gestite
  qui.
- **Aggiornamenti.** `UpdateBanner` controlla all'avvio solo con
  `check_updates`. "Controlla ora" esegue `check()`: nessun aggiornamento → toast
  "Sei aggiornato"; aggiornamento → mostra il banner esistente; errore → toast
  d'errore.

### 8.4 Test

Core: `settings.toml` della 0.1 si carica; valori sconosciuti → predefiniti;
`validate` sugli estremi di ogni intervallo; `SessionOptions` dalle impostazioni
(keepalive 0); `KnownHosts::list` con più host, porte non standard, righe
hashate. UI: navigazione tra categorie e categoria ricordata; tema del terminale
applicato alle schede aperte; riconnessione con orologio finto (sequenza dei
ritardi, nessun tentativo per `auth.*` e `Exited`, "Annulla", stop dopo 5);
conferma alla chiusura di scheda; "Controlla ora" nei tre esiti.

## 9. Compatibilità dei file

- `CONNECTIONS_VERSION` passa da 1 a 2. Motivo: `AuthMethod::Auto` è una
  variante che la 0.1 non sa leggere; con la versione 2 la 0.1 apre il file in
  sola lettura (`LoadOutcome::ReadOnlyNewerVersion`, già esistente e testato)
  invece di segnalarlo come illeggibile, e non può sovrascriverlo perdendo
  colori e icone.
- La 0.2 legge i file versione 1 senza conversione (i campi nuovi sono tutti

Ogni fase lascia `main` funzionante e con CI verde; si rilasciano tutte insieme
come 0.2.0.
