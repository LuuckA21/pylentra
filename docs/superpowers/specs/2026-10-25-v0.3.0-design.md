# Pylentra 0.3.0 — Snippet, note, salti multipli, icona, finestra

- **Data:** 2026-10-25
- **Stato:** in revisione
- **Base:** 0.2.2 (`main` a e4085e7)
- **Mockup:** tela "Pylentra 0.2.0 — direzione visiva" (artifact privato), scheda
  "0.3.0 · Icona dell'app", proposta **B**

## 1. Obiettivo

Cinque migliorie scelte dall'utente:

1. **Snippet:** comandi salvati da inviare al terminale.
2. **Jump host a più salti** nell'import da `~/.ssh/config`.
3. **Note** per connessione e ricerca estesa.
4. **Icona dell'app** al posto del segnaposto.
5. **Stato della finestra** ricordato tra un avvio e l'altro.

**Criteri di successo**

- Uno snippet si salva una volta e si invia a qualsiasi sessione con
  Ctrl+Shift+P, Invio; senza "esegui subito" il testo resta al prompt.
- Uno snippet su più righe non viene mai eseguito riga per riga senza che
  l'utente lo confermi.
- `ProxyJump a,b` importato produce una catena che si connette.
- Una connessione si trova cercando una parola delle sue note o il nome del
  suo gruppo.
- L'icona si riconosce anche a 16 px nella barra delle applicazioni.
- Chiusa massimizzata, l'app si riapre massimizzata; altrimenti con la stessa
  dimensione e posizione.
- La 0.2.2 continua a leggere libreria e impostazioni scritte dalla 0.3.0.

**Fuori ambito:** variabili negli snippet (`{{nome}}`), snippet per gruppo, tag,
vero schermo intero (F11), export/import della libreria, SFTP, schermo diviso,
forward dinamico, macOS.

## 2. Decisioni

| Area | Scelta |
|---|---|
| Archivio snippet | file separato `snippets.toml`, `SnippetStore` nel core |
| Ambito snippet | globale oppure legato a una connessione |
| Invio | `term.paste` di xterm; Invio finale solo con "esegui subito" (default spento) |
| Uso | palette (Ctrl+Shift+P, pulsante nella barra di stato) |
| Gestione | categoria "Snippet" nelle impostazioni + modulo condiviso |
| Note | `Connection.notes: Option<String>`, `connections.toml` resta v2 |
| Finestra | `tauri-plugin-window-state` (dimensione, posizione, massimizzata) |
| Icona | proposta B, con variante semplificata per 16–32 px |

Nuove dipendenze ammesse: `tauri-plugin-window-state` (crate) e il pacchetto
npm del plugin solo se serve all'interfaccia (non previsto).

## 3. Snippet: dati e archivio (core)

### 3.1 Modello (`crates/pylentra-core/src/snippets.rs`)

```rust
pub struct Snippet {
    pub id: Uuid,
    pub name: String,
    pub text: String,
    #[serde(default)]
    pub run: bool,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub connection_id: Option<Uuid>,   // None = globale
}
pub struct SnippetFile { pub version: u32, #[serde(default)] pub snippets: Vec<Snippet> }
pub const SNIPPETS_VERSION: u32 = 1;
```

`Snippet` esportato con ts-rs (`connection_id?: string`).

### 3.2 File e archivio

- `snippets.toml` nella cartella di configurazione, accanto a
  `connections.toml`; il testo multiriga usa le stringhe TOML multiriga.
- `SnippetStore` segue `ConnectionStore` e ne riusa `atomic_write`, `parse` e
  `quarantine`:
  - file assente → elenco vuoto (`CreatedEmpty`);
  - file illeggibile → spostato in backup, elenco vuoto
    (`RecoveredFromCorrupt`);
  - `version` > `SNIPPETS_VERSION` → sola lettura (`ReadOnlyNewerVersion`).
- Operazioni: `upsert(Snippet)`, `delete(Uuid)`,
  `remove_for_connection(Uuid) -> usize`; ognuna una sola scrittura atomica,
  rifiutata con `ReadOnly` in sola lettura.
- Validazione (`Snippet::validate`): `name` non vuoto dopo `trim` e al massimo
  80 caratteri; `text` non vuoto dopo `trim` e al massimo 64 KiB (byte UTF-8).
  Errori `InvalidInput` con `field` = `name` o `text`.

### 3.3 Comandi (`src-tauri`)

- `snippets_get() -> Vec<Snippet>`
- `snippet_save(snippet)`: se `connection_id` è impostato e non esiste nella
  libreria → `config.invalid` con `field = "connection_id"`.
- `snippet_delete(id)`
- `connection_delete`: dopo l'eliminazione della connessione chiama
  `remove_for_connection`; un errore qui va nel log e non annulla
  l'eliminazione (come per il portachiavi).
- `startup_warnings` riporta anche l'esito di `snippets.toml` con gli stessi
  codici della libreria (`config.recovered_corrupt`, `config.read_only`) e il
  parametro `file = "snippets.toml"`.

### 3.4 Test

Core: salvataggio e rilettura; testo multiriga invariato; nome/testo vuoti,
nome di 81 caratteri e testo oltre 64 KiB rifiutati; file assente → vuoto; file
corrotto → backup e vuoto; `version = 2` → sola lettura e scrittura rifiutata;
`remove_for_connection` toglie solo gli snippet di quella connessione.
Comandi: `connection_id` inesistente rifiutato; eliminare una connessione
elimina i suoi snippet; avviso all'avvio per `snippets.toml` corrotto.

## 4. Palette e invio

### 4.1 Apertura

- Ctrl+Shift+P (nuova azione `snippets` in `shortcuts.ts`) o pulsante
  "Snippet" nella barra di stato.
- Solo sulla scheda attiva in fase `ready`; altrove il pulsante è disattivato
  e la scorciatoia non fa nulla.

### 4.2 Componente (`SnippetPalette.svelte`)

- Pannello sopra il terminale (stile di `ForwardPanel`/`.tab-panel`), con un
  campo di ricerca.
- Ricerca su nome e testo, senza maiuscole né accenti (`fold` esportato da
  `search.ts`).
- Ordine: gli snippet della connessione della scheda (intestazione col nome
  della connessione), poi i globali (intestazione "Globali"); alfabetico dentro
  ogni gruppo. Le schede rapide vedono solo i globali.
- Voce: nome, prima riga del testo attenuata, pillola "esegue" se `run`.
- Tastiera come `QuickConnect`: frecce, Invio, Esc. Alla chiusura il focus
  torna al terminale.
- In fondo: "Nuovo snippet" e, se il terminale ha una selezione non vuota,
  "Salva la selezione come snippet" (apre `SnippetForm` con il testo
  selezionato e `connection_id` della scheda, `null` per una scheda rapida).
- Elenco vuoto: messaggio e "Nuovo snippet".
- ARIA: `role="dialog"`, campo `combobox` con `aria-controls` e
  `aria-activedescendant`, elenco `listbox` con `option`, intestazioni dei
  gruppi annunciate (`role="group"` con `aria-label`).

### 4.3 Invio

1. `term.paste(text)` (xterm: bracketed paste se la shell l'ha attivato,
   conversione delle andate a capo come un incolla).
2. Se `run`, dopo l'incolla si invia `\r`.
3. **Protezione:** se `text` contiene un'andata a capo, `run` è falso e
   `term.modes.bracketedPasteMode` è falso, prima di inviare compare
   `ConfirmDialog`: "Questa shell eseguirà ogni riga appena incollata.
   Continuare?". Annulla non invia nulla.
4. La destinazione è la scheda da cui la palette è stata aperta.

### 4.4 Test

Filtro per nome e testo con accenti; ordine connessione → globali; Invio chiama
`paste(text)` e invia `\r` solo con `run`; multiriga + niente bracketed paste +
`run` falso → conferma, Annulla non invia; multiriga con bracketed paste → nessuna
conferma; Esc chiude e il focus torna al terminale; Ctrl+Shift+P solo sulla
scheda attiva e `ready`; "Salva la selezione" solo con una selezione; scheda
rapida → solo globali.

## 5. Gestione nelle impostazioni

### 5.1 Categoria "Snippet"

- Sesta categoria in `Settings.svelte`, dopo "Connessioni", con l'icona nuova
  `snippet` (parentesi graffe) in `Icon.svelte`; componente
  `settings/SnippetsSection.svelte`.
- Ricerca in cima (stesso filtro della palette) e "+ Nuovo snippet".
- Gruppi: "Globali", poi un gruppo per connessione che ha snippet (nome e
  `Avatar`).
- Riga: nome, prima riga del testo, pillola "esegue", "Modifica" ed "Elimina"
  (con `ConfirmDialog`).
- Sola lettura (`snippets.toml` di una versione più nuova): avviso e comandi di
  modifica disattivati.

### 5.2 Modulo (`SnippetForm.svelte`)

Dialogo condiviso tra impostazioni e palette:

- **Nome** (obbligatorio, massimo 80 caratteri).
- **Testo** (obbligatorio, area multiriga con il font del terminale).
- **Esegui subito** (interruttore, spento di default; aiuto "Invia anche Invio
  dopo il testo").
- **Disponibile in**: "Tutte le connessioni" + le connessioni della libreria in
  ordine alfabetico; dalla palette preimpostato sulla connessione della scheda.
- Validazione lato interfaccia con gli stessi limiti del core; un
  `config.invalid` del core appare accanto al campo indicato.

### 5.3 Store (`ui/src/lib/stores/snippets.svelte.ts`)

`snippets` (elenco + `readOnly`), `loadSnippets()` all'avvio insieme alla
libreria, `saveSnippet`, `deleteSnippet` che ricaricano dopo ogni modifica.
Dopo `deleteConnection` si ricaricano anche gli snippet. `readOnly` deriva da
`startup_warnings` con `file = "snippets.toml"`.

### 5.4 Test

La categoria mostra i gruppi; il modulo salva nome, testo, `run` e
`connection_id`; "Disponibile in" preimpostato dalla palette; nome o testo vuoti
mostrano l'errore e non salvano; errore del core accanto al campo; Elimina con
conferma chiama `snippetDelete`, Annulla no; sola lettura disattiva i comandi.

## 6. Note e ricerca

- `Connection.notes: Option<String>` con `#[serde(default,
  skip_serializing_if = "Option::is_none")]` e `#[ts(optional)]`; il core salva
  come `None` una nota vuota dopo `trim`. `Connection::validate`: al massimo 4 KiB, altrimenti
  `InvalidInput { field: "notes" }`.
- `connections.toml` resta alla versione 2. La 0.2.2 legge un file della 0.3
  (ignora i campi sconosciuti); se poi salva una connessione, le sue note si
  perdono. Il CHANGELOG lo dice.
- Modulo connessione: campo "Note" multiriga in fondo alla sezione "Aspetto".
- Barra laterale: icona `note` accanto al nome delle connessioni con note,
  `title` con il testo e `aria-description` con i primi 200 caratteri.
- Ricerca: `matches(c, query, groups)` su nome, host, utente, note e nome del
  gruppo; usata da barra laterale e connessione rapida.
- Test: note salvate e rilette; oltre 4 KiB rifiutate; ricerca da note e da
  nome del gruppo; icona e descrizione solo con note; un file senza `notes` si
  carica.

## 7. Jump a più salti nell'import

- `ProxyJump h1,h2,…,hn` (dopo `trim`, senza voci vuote) diventa una catena:
  target → `hn`, `hn` → `hn-1`, …, `h2` → `h1`. Ogni salto deve risolversi a un
  alias importato o a una connessione salvata (stessa regola del salto
  singolo, nomi senza maiuscole).
- **Conflitti:** la catena si converte solo se ogni salto che deve ricevere un
  jump lo ha già uguale o non ne ha. Una connessione salvata non viene mai
  modificata: se un salto salvato ha un jump diverso da quello richiesto la
  catena non si converte. In caso di conflitto il target non riceve jump e ha
  la nota `MultiHopJump` (già esistente). Un salto non risolvibile dà le note di
  oggi (`UnknownJump`, `JumpNotAlias`).
- Ogni candidato a cui la catena assegna un jump riceve la nuova nota
  `ImportNote::ChainedJump { target: String }` ("jump host impostato dalla
  catena di <target>"), tradotta come le altre (`import.note.ChainedJump`).
- L'ordine di elaborazione deve dare lo stesso risultato qualunque sia l'ordine
  dei blocchi nel file.
- Giri e catene oltre 5 salti restano gestiti da `brokenJumps`/`prepare` e dal
  core.
- Test (parser): `a,b` con salti senza jump → catena e nota `ChainedJump` su `b`;
  `b` con un jump diverso → `MultiHopJump` e nessun jump sul target; salto
  salvato con jump compatibile → catena senza modificarlo; tre salti; salto
  sconosciuto → nota; due target con catene compatibili che condividono salti →
  entrambe convertite.

## 8. Icona

- Sorgenti in `src-tauri/icons/source/`: `icon.svg` (proposta B, 1024 px) e
  `icon-small.svg` (proposta B semplificata: tratto della "P" più spesso,

  alla build.
- I file generati sono committati; il README ("Icons") spiega come rigenerarli.
- Verifica: immagini a 16, 32, 48, 128, 256 px allegate alla PR.
