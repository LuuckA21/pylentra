# Pylentra 0.8.0 (SFTP) — piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** pannello file SFTP accanto al terminale: sfoglia, scarica e carica file e cartelle sulla connessione già aperta della sessione.

**Architecture:** un compito SFTP per sessione, aperto su richiesta sulla `chain.target` della sessione (`ssh/sftp/`), con coda di trasferimenti, eventi `SessionEvent::Transfer` sul canale eventi esistente e domande dei conflitti via `PromptBroker`. Comandi Tauri sottili che aprono i dialoghi da Rust e ricevono il trascinamento dalla finestra. Nella UI un `FilePanel` per `TerminalPane`.

**Tech Stack:** Rust 2024 (MSRV 1.90), `russh` 0.64, `russh-sftp` 3.0.1, `futures-util` (già nel lockfile), Tauri 2, Svelte 5, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-10-v0.8.0-design.md`. Va letta insieme a questo piano: le regole di sicurezza (§4) valgono per ogni task.

## Global Constraints

- Limiti: profondità massima **32**; al massimo **100 000** elementi per trasferimento; al massimo **100 000** voci per elenco (`truncated: true` se supera).
- Blocchi da **32 KiB** (o `limits@openssh.com` se più piccolo), al massimo **8** richieste in volo per file.
- Avanzamento `Running` al massimo ogni **200 ms**, più uno a fine di ogni file.
- Temporanei: `<nome>.<n>.pylentra-tmp`, creati esclusivi su entrambi i lati.
- Impostazioni: `sftp_show_hidden: bool` (default `false`), `sftp_panel_width: f32` (default `0.3`, valida **0.15–0.6**).
- Codici di errore nuovi: `sftp.unavailable`, `sftp.permission_denied`, `sftp.limit`. Si riusano `not_found`, `cancelled`, `io`, `ssh.protocol`.
- Nessun comando Tauri accetta un percorso locale dall'interfaccia.
- Log: solo codici ed id, mai percorsi, nomi o contenuti.
- Ogni testo nuovo in `en.ts` **e** `it.ts`.
- Binding generati con `cargo test` (ts-rs): dopo ogni modifica ai tipi esportati, `git diff ui/src/lib/bindings` deve contenere solo i cambi attesi, e vanno committati.
- Prima di ogni commit: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, i test toccati; per la UI `pnpm --dir ui lint`, `check`, `test`.

## Review Focus

1. **Lettura corta prima della fine del file:** il server risponde a una read con meno byte di quelli chiesti. Ci si aspetta che il pezzo mancante venga richiesto di nuovo e che il file arrivi intero. Test nel Task 5 (server di test "half reads").
2. **File che cambia dimensione durante il download:** si trasferiscono i byte indicati da `fstat` all'apertura. Una EOF anticipata dà `Skipped(Error)` e nessun file finale. Test nel Task 5.
3. **Connessione che cade a metà upload:** il temporaneo remoto non si può cancellare. Ci si aspetta `Failed` e nessun file finale corrotto; il temporaneo può restare sul server e va scritto nei limiti del README. Test nel Task 6.
4. **Conflitto con un nome che differisce solo per maiuscole** (`A` e `a` scaricati su Windows o macOS): il secondo trova il primo come "esistente" e viene fatta la domanda; non sovrascrive in silenzio. Test nel Task 5, simulato con un file già presente.
5. **Rilascio fuori da un pannello file, o due rilasci di fila:** un `drop_id` vecchio o già usato viene rifiutato e niente viene caricato. Test nel Task 8.

**Interfaces:**

- Produces:
  - `SessionManager::sftp_download(&self, id, items: Vec<String>, local_dir: PathBuf) -> Result<u32, CoreError>`: mette in coda e restituisce subito l'id (dal contatore per sessione, che parte da 1).
  - `SessionManager::sftp_cancel(&self, id, transfer_id: u32) -> Result<(), CoreError>`: rimuove dalla coda o imposta il flag del trasferimento in corso.
  - `copy::download_file(sftp, remote: &str, local: &Path, size: u64, modified: Option<u64>, cancel: &AtomicBool, progress: &mut impl FnMut(u64)) -> Result<(), CoreError>`:
    - `create_temp`;
    - letture `futures_util::stream::iter(offsets).map(read).buffered(8)`;
    - una lettura corta prima di `size` richiede di nuovo il resto, prima del blocco successivo;
    - EOF prima di `size` → `CoreError::NotFound { what: "file changed" }`;
    - `File::set_modified`, poi `fs::rename(tmp, local)`;
    - qualunque uscita senza successo cancella il temporaneo.
  - Un trasferimento, in ordine:
    1. evento `Queued`;
    2. `scan_remote`;
    3. per ogni cartella: `create_dir` sotto `local_dir`; se esiste ed è un link o un file, si salta con tutto il contenuto;
    4. per ogni file: se la destinazione esiste ed è un link → `Symlink`; altrimenti si fa la domanda dei conflitti, ricordando la scelta con `all`;
    5. `Running` al massimo ogni 200 ms;
    6. alla fine `Finished`, `Failed` o `Cancelled`.
