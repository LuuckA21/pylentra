# Pylentra 0.4.0 — Piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** campi sconosciuti conservati nei file di configurazione, forward
dinamico SOCKS5, variabili negli snippet, schermo intero con F11.

**Architecture:** il core riceve `extra: toml::Table` (`serde(flatten)`) sulle
strutture salvate, con gli store come proprietari; `connections.toml` passa
alla v3. Un modulo puro `ssh/socks.rs` fa l'handshake SOCKS5 e `ssh/forward.rs`
lo collega ai canali `direct-tcpip` come i forward locali. L'interfaccia
aggiunge il terzo tipo di forward, il dialogo delle variabili e F11 in
`App.svelte`.

**Tech Stack:** come la 0.3 (Rust 2024, russh, tokio, ts-rs 12, Tauri 2,
Svelte 5, xterm.js 6, Vitest). Nessuna dipendenza nuova.

**Spec:** `docs/superpowers/specs/2026-10-27-v0.4.0-design.md`, da leggere
insieme a questo piano. I riferimenti `§n` sono sezioni della spec.

## Global Constraints

- Nessuna dipendenza nuova (Rust o npm).
- `CONNECTIONS_VERSION = 3`; `SNIPPETS_VERSION` resta 1.
- `extra` è sempre `#[serde(flatten)] #[ts(skip)] pub extra: toml::Table` e non compare nei tipi TS.
- Gli store sono proprietari di `extra`: in aggiornamento vince quello salvato con lo stesso id, l'`extra` arrivato dall'IPC è ignorato; un elemento nuovo parte vuoto.
- SOCKS: solo versione 5, metodo 0x00, comando CONNECT; risposte `0x00` successo, `0x01` errore generico, `0x04` host irraggiungibile, `0x07` comando non supportato, `0x08` tipo di indirizzo non supportato; `05 FF` se manca il metodo 0x00; handshake entro 10 s. Ascolto di default `127.0.0.1:1080`.
- Variabili: `{{nome}}`, nome 1–40 caratteri in `[A-Za-z0-9_-]`, spazi ammessi attorno; `{{{{` → `{{`; il resto tra `{{ }}` è testo. Ultimi valori solo in memoria.
- F11 senza modificatori; permesso `core:window:allow-set-fullscreen`; non ricordato alla riapertura.
- Ogni testo visibile passa da `t()`; ogni chiave nuova va in `ui/src/lib/i18n/en.ts` **e** `it.ts`.
- Binding TS rigenerati con `cargo test -p pylentra-core` e committati.
- Prima di ogni commit, dalla radice: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, `pnpm --dir ui lint`, `pnpm --dir ui check`, `pnpm --dir ui test`. `mkdir -p ui/dist` per `src-tauri`; build con `CARGO_INCREMENTAL=0`.
- Il core non usa `unwrap`/`expect`/`panic` fuori dai test.
- Commit con il trailer del repository; push solo su `claude/awesome-cannon-6elqn5`.

## Review Focus

1. **Client SOCKS che manda saluto e richiesta CONNECT in un'unica scrittura** (curl lo fa) — l'handshake deve funzionare lo stesso. Test in Task 3.
2. **Nome a dominio vuoto o lungo 255 byte nella richiesta SOCKS** — vuoto rifiutato con `0x01`, 255 accettato. Test in Task 3.
3. **Due client SOCKS contemporanei sullo stesso forward** — entrambi raggiungono la destinazione. Test in Task 4.
4. **Un valore di variabile che contiene `{{x}}`** — viene incollato così com'è, senza essere espanso di nuovo. Test in Task 7.
5. **Un campo sconosciuto dentro una regola di forward** (`[[connections.forwards]] … futuro = 1`) — il file si carica comunque (il campo si perde al salvataggio, come da §3.1). Test in Task 1.

## Fase 2 · SOCKS

### Task 3: Handshake SOCKS5 (`ssh/socks.rs`)

**Files:**
- Create: `crates/pylentra-core/src/ssh/socks.rs`
- Modify: `crates/pylentra-core/src/ssh/mod.rs` (`mod socks;`)

**Interfaces:**
- Produces:
  - `pub(crate) const HANDSHAKE_TIMEOUT: Duration = Duration::from_secs(10);`
  - `pub(crate) enum SocksError { Io(io::Error), Timeout, BadVersion, NoAcceptableMethod, Rejected(u8) }`
  - `pub(crate) async fn handshake<S: AsyncRead + AsyncWrite + Unpin>(s: &mut S, deadline: Duration) -> Result<(String, u16), SocksError>` — scrive da sé le risposte di rifiuto (`05 FF`; `0x07`; `0x08`; `0x01` per nome vuoto) prima di restituire l'errore; per un errore di versione non scrive nulla. Un IPv6 diventa la stringa dell'indirizzo senza parentesi.
  - `pub(crate) async fn reply<S: AsyncWrite + Unpin>(s: &mut S, code: u8) -> io::Result<()>` — `05 code 00 01 00 00 00 00 00 00`.

- [ ] **Step 1: Test** (client finto su `duplex`, poi `handshake(&mut server, Duration::from_millis(200))`):
  - `connect_ipv4`: `05 01 00` + `05 01 00 01 0a 00 00 01 1f 90` → `("10.0.0.1", 8080)`, il client riceve `05 00`.
  - `connect_ipv6` → `("::1", 22)`; `connect_domain` (`03 0b "example.com"`) → `("example.com", 443)`.
  - `greeting_and_request_in_one_write` (Review Focus 1): tutti i byte in una sola `write_all` → ok.
  - `domain_255_bytes_ok` e `empty_domain_rejected` (Review Focus 2): il secondo riceve `05 01 …` e `Rejected(1)`.
  - `password_only_rejected`: `05 01 02` → client riceve `05 FF`, `NoAcceptableMethod`.
  - `bind_command_rejected` → risposta `0x07`; `unknown_addr_type_rejected` (0x05) → `0x08`.
  - `socks4_closed`: primo byte `04` → `BadVersion`, nulla scritto.
  - `truncated_request`: client chiude a metà → `Io`.
  - `silent_client_times_out`: client non scrive → `Timeout` entro 200 ms.
- [ ] **Step 2: `cargo test -p pylentra-core socks`** → FAIL.
- [ ] **Step 3: Implementare** `socks.rs` (`tokio::time::timeout` attorno alla lettura di saluto e richiesta).
