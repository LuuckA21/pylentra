# Pylentra 0.6.0 — Piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** esportare la libreria (gruppi, connessioni, snippet) in un file TOML
senza segreti e reimportarla, anche su un altro PC, con un'anteprima.

**Architecture:** un modulo puro `crates/pylentra-core/src/export.rs` scrive e
legge il file e calcola anteprima e piano d'import (id nuovi, riferimenti
ricollegati). Gli store aggiungono un import in una sola scrittura. Tre comandi
Tauri leggono e scrivono il file scelto con i dialoghi di sistema
(`tauri-plugin-dialog`); la UI aggiunge la sezione Libreria, due voci nel menu
"⋯" e il dialogo d'anteprima.

**Tech Stack:** Rust 2024, serde + toml 1, ts-rs, Tauri 2 (+ `tauri-plugin-dialog`),
Svelte 5, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-30-v0.6.0-design.md`, da leggere
insieme a questo piano. I riferimenti `§n` sono sezioni della spec.

## Global Constraints

- Unica dipendenza nuova: il crate `tauri-plugin-dialog` in `src-tauri`, usato da Rust (`DialogExt`). Nessun pacchetto npm e nessun permesso `dialog:*`: i percorsi non passano mai dall'interfaccia (ruling dopo la review del Task 4, spec §2/§6). `cargo deny check` deve passare.
- `EXPORT_FORMAT = "pylentra-export"`, `EXPORT_VERSION = 1`; nome proposto `pylentra-export-AAAA-MM-GG.toml`, filtro `toml`.
- Mai segreti nel file: solo i campi di `Connection` (per l'auth: `save`, `path`, `save_passphrase`); `extra` mai esportato.
- File letto solo se è un file normale e al massimo 5 MB (`MAX_EXPORT_BYTES = 5 * 1024 * 1024`).
- Id sempre nuovi all'import; gruppi uniti per nome esatto; duplicato = stessa connessione per nome esatto.
- `CONNECTIONS_VERSION` e `SNIPPETS_VERSION` non cambiano.
- Il core non usa `unwrap`/`expect`/`panic` fuori dai test; nuovi tipi visti dalla UI con `#[ts(export)]` e binding committati.
- Ogni testo visibile passa da `t()`; ogni chiave nuova in `ui/src/lib/i18n/en.ts` **e** `it.ts`.
- Prima di ogni commit: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` (con `mkdir -p ui/dist`, `CARGO_INCREMENTAL=0`), `git diff --exit-code ui/src/lib/bindings` dopo i test, `pnpm --dir ui lint`, `pnpm --dir ui check`, `pnpm --dir ui test`.
- Commit con il trailer del repository; push solo su `claude/awesome-cannon-6elqn5`.

## Review Focus

1. **File modificato a mano con un `jump_via` verso un id che non è nel file** — nessun errore: si comporta come un jump host non selezionato (esistente per nome, altrimenti nessuno). Test in Task 2.
2. **Snippet con `connection_id` verso un id che non è nel file** — scartato e non contato come importato, nessun errore. Test in Task 2.
3. **Due gruppi del file con lo stesso nome** — finiscono nello stesso gruppo (esistente o uno solo nuovo). Test in Task 2.
4. **Import in una libreria in sola lettura** — errore mostrato nel dialogo, nessun file scritto (né connessioni né snippet). Test in Task 4.
5. **Export con `snippets.toml` non disponibile** — la libreria viene esportata lo stesso, senza snippet, e la UI avvisa che gli snippet non ci sono. Test in Task 4 e 5.
